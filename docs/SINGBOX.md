# sing-box 用户节点

fluxlite 的 sing-box 用户节点和 Realm 链路是两个独立功能。Realm 负责多跳端口转发；sing-box 用户节点负责在一台已纳管 VPS 上创建独立的客户端入口、周期额度和客户端配置。

## 隔离方式

每个面板用户使用一个独立 systemd/OpenRC 服务：

```text
/etc/fluxlite/singbox/<id>/config.json
/etc/fluxlite/singbox/<id>/server.crt
/etc/fluxlite/singbox/<id>/server.key
/var/lib/fluxlite-singbox/<id>/
/var/lib/fluxlite-singbox/<id>/access.log    连接日志（info 级别，供流量审计读取）
fluxlite-singbox-<id>.service 或 fluxlite-singbox-<id>
```

每个服务以独立系统用户 `fluxlite-sb-<id>` 运行，配置目录和数据目录归这个用户所有；限速靠这个身份给它的流量打标记。删除节点时连同这个系统用户一起删除。

连接日志超过 20MB 且已被面板读完时会被清空，不会无限增长。

服务之间不共享配置。停止、删除或达到额度只影响一个用户。面板不会覆盖 `/etc/sing-box/config.json`，也不会修改一键脚本创建的 `/etc/sing-box/conf.d/*.json`。

当前面板部署要求目标节点已经安装可执行的 `sing-box`。Debian/Ubuntu 使用 systemd，Alpine 使用 OpenRC；配置写入后先执行 `sing-box check`，校验通过才启用服务。

## 协议

创建时一次选择一种协议：SS2022、AnyTLS、VLESS Reality、Hysteria2、TUIC、Trojan、VMess 或 VLESS TLS。TLS 类协议生成独立自签证书，导出的客户端链接带允许自签的参数。

凭据和完整配置使用面板主密钥加密保存；列表接口和审计日志不返回密码、UUID、私钥或链接。导出操作要求管理员登录。

## 流量额度

- 入站与出站字节相加计入额度；基础额度留空表示无限，不执行额度暂停。
- 连接有效期独立设置，默认永久；选择具体日期后到期只停用连接。
- 流量周期从创建时间起计算 30 天，与连接有效期相互独立。
- 周期到期后已用量和本周期追加额度清零，基础额度恢复。
- “增加额度”只增加当前周期额度，不改变周期结束时间或已用量。
- “减少额度”先扣减本周期追加额度，再扣减基础额度；不能减少到低于已用量，无限额度不能直接减少。
- “清零重置”只清零当前周期已用量，不改变周期结束时间。
- 周期到期时，仍未到连接有效期的节点会自动进入下一个 30 天周期；用量清零、追加额度清零，周期结束时间顺延 30 天，已暂停的节点会自动恢复。
- 达到额度后面板停止该用户的独立服务；增加额度、清零或进入下一周期后可以恢复。

统计依赖目标节点上的 `iptables`/`ip6tables` 计数规则。流量轮询存在一个采集周期的过冲，计数口径包含协议和网络头部，不等于服务商账单的计费口径。

计数规则只存在于内核里：机器重启或防火墙重载（ufw、firewalld 等）会把它们清掉。面板采样时发现规则缺失，会自动补回并重新读取，日志里留一条 `sing-box accounting rules were missing and have been restored`。规则丢失到补回之间的流量（最多一个采集周期）无法追回。机器上没有 `iptables` 时不会尝试修改防火墙，只报错。

## 限速

- 上行、下行可分别设置，单位 Mbps，0 表示不限，最大 100000。
- 实现方式：用 iptables mangle 按节点的系统用户给流量打标记，再由默认出口网卡上的 `tc` police 过滤器限速，超出部分丢弃。
- 目标机需要 `tc`（iproute2）和 `iptables`/`ip6tables`，并且能识别默认路由的网卡。条件不满足时节点照常运行，卡片上标「限速未生效」。
- 保存节点编辑时会重启一次该节点的服务，以确认它以独立系统用户运行；已连接的客户端会断开重连。

## 在线状态与开关

- 卡片上的“在线/离线”表示客户端是否有实际代理会话，不表示 sing-box 服务进程是否正在运行。
- TCP 通过目标机的已建立连接判断；UDP 在安装了 `conntrack` 时读取会话，没有 `conntrack` 时以最近一次计数器增量作为活动兜底。
- 在线状态按 `sample-interval` 采样，前端每 5 秒刷新一次。无客户端连接时会显示“离线”。
- 卡片右侧开关是管理员可用性开关：打开只代表允许该节点接入，关闭会停止该用户服务；在线状态不会反向修改这个开关。

## 外部节点扫描

“扫描已有节点”只读取 `/etc/sing-box/conf.d/*.json`，返回协议、端口、标签和共享服务状态，不写文件、不重启服务，也不自动套用额度。扫描结果会以 `external` 记录展示。

点击“接管”后，面板先读取共享服务状态并备份片段，再迁移到独立服务并校验。成功后原片段改名为 `.json.disabled`，避免共享服务重复监听。失败时清理新建的独立服务、恢复原片段及共享服务原有运行状态；若回滚失败会明确报错，记录不改为面板管理。

- 原共享服务运行时才短暂停止并重新启动；原来停止时保持停止，即使还有其他片段。
- 不修改共享服务的开机启用状态，不自动解除 systemd mask；停止且 masked 的服务不再被强行启动。
- 运行中但 masked，或服务仍在启动/停止中的状态会在迁移前拒绝接管，需管理员先确认状态。

外部节点与面板管理节点使用不同配置和服务命名空间，可以共存，但端口不能重复。

## 导出接管节点

接管成功后，点击节点的二维码按钮可查看节点链接、二维码和 sing-box 客户端 `outbounds` 配置。导出使用原密码或 UUID，不重新生成凭据；客户端配置不包含服务端 `inbounds`、私钥或证书文件路径。

旧版本已接管、但只保存了服务端配置的节点，会在导出时从已加密保存的原配置重建客户端信息。无需重新接管、改密码或重新部署服务，也不修改数据库中的原配置。

- 自动导出要求端口对应唯一入站，并能确定唯一用户。多用户入站不能任意选一个用户，需先明确拆分后再导出。
- 支持面板列出的协议及可完整转换的传输参数，不保证任意外部配置都能生成链接。缺失凭据、重复入站或不支持的自定义 TLS/传输参数会明确报错，不返回空链接或将服务端 JSON 当作客户端配置。
- 接管节点直接从宿主机的原始入站配置重建客户端配置：TLS SNI、Reality 握手域名/公钥/短标识、传输和协议字段会按原配置导出；SS2022 不显示无关的 TLS 控件。
- AnyTLS 等协议的分享链接可包含仅存在于客户端的附加字段。若该字段不在宿主机入站配置中（例如任意自定义 SNI 或 `insecure=1`），服务端本身没有可反推的数据，导出会保留安全默认值而不会猜测一个错误参数。
- 面板新建的自签 TLS 节点保留其明确设置的跳过证书校验行为，导出时会提示风险。使用受信任证书时，应在客户端开启校验并设置正确的 SNI。
- 二维码生成失败时仍可复制节点链接和客户端 JSON；长链接在弹窗内换行，JSON 可在独立区域滚动查看，不需要依赖二维码导入。

节点链接和客户端 JSON 含连接凭据，请只交给需要使用该节点的人。

## 回滚

删除面板管理用户时只停止对应的 `fluxlite-singbox-<id>.service` 并删除该用户目录。Realm 链路、共享 `sing-box` 服务和一键脚本配置不受影响。

### 导出地址选择

二维码与节点连接默认使用机器保存的主机地址（通常为 IPv4），不再被探测到的 IPv6 自动覆盖。存在 IPv6 地址时可在弹窗切换；节点链接、二维码和客户端 JSON 同步重新生成。IPv6 入口地址优先于探测地址。仅有 IPv6 的机器默认使用 IPv6；不存在的地址族不会伪造或静默回退。此操作不重建服务、不更换密钥，也不改变服务端监听配置。
